# E90 OS — iDrive Heritage

## Задача для Claude

Разработай полноценный Android-лаунчер / интерфейс автомагнитолы BMW E90 на основе **семи PNG-референсов в папке `screens/`**. Изображения показывают согласованный дизайн разных состояний **одного интерфейса**, а не семь отдельных приложений.

Автомобиль: BMW E90 320i, 2007 г. Магнитола: Android 10, KSW `Ksw-Q-Userdebug_OS_v2.3.1`, платформа Qualcomm MSM8953, 4 ГБ ОЗУ / 64 ГБ. MCU: `415187dLZH-CIC-GTL-200904-B18`.

### Файлы

1. `screens/01-home.png` — главный экран: обзор маршрута, компактный музыкальный плеер.
2. `screens/02-navigation.png` — навигация: крупная карта и подсказка поворота.
3. `screens/03-music.png` — музыкальный плеер.
4. `screens/04-phone.png` — телефон, Bluetooth и последние вызовы.
5. `screens/05-apps.png` — каталог приложений.
6. `screens/06-vehicle.png` — информация об автомобиле.
7. `screens/07-settings.png` — настройки экрана, звука, Bluetooth и оформления.

### Неподвижный каркас и стиль

- Каждый PNG — **полноэкранный бесшовный макет**. Никаких рамок дисплея, карточек вокруг всего экрана, внешних отступов или подписей снаружи.
- Референсы приблизительно **2048 × 768 px, соотношение 8:3**. Реальное разрешение и плотность пикселей устройства выяснить до финальной сборки; интерфейс должен адаптироваться без искажения.
- Верхняя глобальная полоса (бренд `E90 OS`, время, индикатор масла, АКБ) остаётся в одинаковых координатах на всех экранах.
- Справа единое вертикальное меню из шести разделов: **Навигация, Музыка, Телефон, Приложения, Автомобиль, Настройки**. При смене экрана меняется только активная оранжевая строка и содержимое слева. Правое меню не должно дёргаться или пересоздаваться визуально.
- Слева основная рабочая область; косая граница правого меню остаётся на прежнем месте. Фон непрерывный, без заметных стыков.
- Палитра: почти чёрный графит `#0B0E12`, тёмно-серый, белый, серебристые обводки; акцент тёплый янтарно-оранжевый примерно `#F28A24`. Без ярких многоцветных карточек. Иконки — тонкие, единый stroke, можно использовать Iconoir или Tabler Icons.
- Кнопки достаточно крупные для управления в автомобиле. Поддержи аппаратную кнопку «Назад», корректное восстановление после сна, автозапуск оболочки только после явного включения пользователем и возможность вернуться к штатному KSW-интерфейсу.

### Поведение

- Сделай семь реальных интерактивных экранов по референсам и плавное переключение без вспышек белого фона.
- Навигация: выбор установленного навигатора / интеграция с доступным навигационным приложением после проверки API. Карта и маршрут на картинках — демонстрационные.
- Музыка: Android MediaSession / активный медиаплеер, реальное название трека и управление воспроизведением при наличии доступа.
- Телефон: работай через доступные Bluetooth/телефонные функции устройства, не имитируй возможность звонка, если API не даёт её.
- Приложения: показывай реально установленные разрешённые для запуска приложения.
- Автомобиль: данные по CAN, батарее, уровню масла, топливу, дверям и запасу хода выводить **только если достоверно получены**. Все цифры на референсах (`12.6 В`, `58%`, `320 км`, `+18 °C`) — **DEMO**, пока нет проверенного источника. Если поле недоступно — показать «Нет данных», а не выдуманное значение.
- Настройки: яркость, ночная тема, настройки аудио и внешний вид. Не подменяй системные настройки KSW там, где нет поддерживаемого интерфейса.
- Подсветку фар и фактическое состояние света пока **не реализовывать**: эту задачу отложили.

### Ограничения и порядок разработки

1. Сначала проанализируй совместимость Android 10, платформы KSW и доступные интерфейсы для управления мультимедиа/автомобильными данными.
2. Сделай безопасный отдельный Android APK с прототипом всех экранов; **не прошивай MCU и не заменяй системный образ**.
3. Сохрани существующие функции штатного KSW и возможность возврата к оригинальному лаунчеру.
4. Реализуй UI-компоненты кодом (Kotlin/Java + Android UI) по изображениям. Не делай интерфейс из одной растянутой PNG: текст, кнопки, виджеты и состояния должны быть настоящими.
5. Сначала покажи структуру проекта, план подключения источников данных и что будет работать сразу, а что потребует изучения KSW/CAN. После согласования можно собирать APK.

**Ключевой критерий:** визуально близко к PNG, единое положение верхней панели и правого меню, плавное переключение, честное отображение доступности данных.
