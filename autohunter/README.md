# AutoHunter — поиск выгодных автомобилей с пробегом

Система обнаруживает новые объявления (BMW, Mercedes-Benz, Audi), оценивает рыночную стоимость по сопоставимым
предложениям, считает рейтинг 0–100 и присылает интересные варианты в Telegram. Веб-панель: лента, фильтры,
аналитика рынка, мониторинг источников.

> **Статус честно.** Работает и проверено автотестами и запуском: ядро (нормализация, дубли, оценка, рейтинг),
> демо-источник, API, веб-интерфейс, PostgreSQL + Alembic. **Не проверено на живых данных:** адаптер ApiAd (нет ключа),
> Telegram-бот (нет токена; логика покрыта тестами с подменой транспорта). Авито/Дром/Авто.ру напрямую не
> опрашиваются — публичного поискового API нет (см. [docs/SOURCES.md](docs/SOURCES.md)). Целевая задержка 15–30 с
> **не заявляется как достигнутая**: её нужно измерить на реальном источнике.

## Быстрый старт (демо, без ключей)

```bash
cd autohunter
cp .env.example .env          # затем задайте AUTH_PASSWORD и AUTH_SECRET
docker compose up -d --build
```

Откройте http://localhost:8000, войдите паролем из `.env`. Через ~10 секунд появятся ~450 синтетических
объявлений с оценками; затем раз в несколько секунд приходят «новые». Вверху панели виден баннер «демонстрационный режим».
Тестовое уведомление: **Мониторинг → «Отправить тестовое уведомление»**.

Данные хранятся в томе `pgdata` и переживают `docker compose restart` / `down` (но не `down -v`).
Сервисы перезапускаются автоматически (`restart: unless-stopped`).

### Без Docker (SQLite)
```bash
cd backend && python3.12 -m venv .venv && . .venv/bin/activate && pip install -r requirements-dev.txt
cd ../frontend && npm ci && npm run build && cd ../backend
AUTH_PASSWORD=secret AUTH_SECRET=$(python -c "import secrets;print(secrets.token_urlsafe(32))") uvicorn app.main:app --port 8000
```
Для разработки фронтенда: `npm run dev` (порт 5173, проксирует `/api` на :8000).

## Подключение реальных источников

1. Решите вопрос с оплатой (см. [docs/SOURCES.md](docs/SOURCES.md)) — **я подписок не оформлял**.
2. В `.env`:
   ```
   SOURCES_ENABLED=apiad_avito,apiad_drom      # demo можно оставить для сравнения: demo,apiad_avito
   APIAD_API_KEY=<ключ из личного кабинета apiad.ru>
   APIAD_QUERIES=BMW,Mercedes-Benz,Audi
   ```
3. Сверьте формат ответа с реальным: `docker compose exec app python -m app.cli apiad-probe` — выведет
   первые нормализуемые записи. Если поля `params` отличаются, поправьте `PARAM_KEYS` в `backend/app/sources/apiad.py`.
4. Следите за вкладкой «Мониторинг»: ошибки, последнее успешное обновление, задержка (средняя и p95).
5. Новый источник = один класс-наследник `SourceAdapter` (`fetch(ctx) → FetchResult`) + строка в `sources/registry.py`.

Адаптеры соблюдают тайм-ауты, ограничение частоты (`RateLimiter`), повторы с экспоненциальной паузой (учитывают
`Retry-After`). 401/403 не повторяются — защиту/капчу система **не обходит**. Сбой одного источника не влияет на другие;
после серии ошибок интервал опроса растёт (до `MAX_BACKOFF_SECONDS`) и возвращается к норме после успеха.

## Telegram

1. Создайте бота у @BotFather, положите токен в `TELEGRAM_BOT_TOKEN`.
2. Задайте `TELEGRAM_PAIRING_CODE=<секретное слово>` и отправьте боту `/start <секретное слово>` — чат
   зарегистрируется. (Или явно: `TELEGRAM_ALLOWED_CHAT_IDS=123456789`.) Незнакомые чаты игнорируются.
3. `docker compose up -d`. Команды: `/top`, `/filters`, `/set <параметр> <значение>`, `/pause`, `/resume`,
   `/status`, `/test`, `/help`. Под сообщением кнопки: открыть объявление, аналоги, в избранное, скрыть.
   Примеры: `/set price_max 900000`, `/set brands BMW,Audi`, `/set seller private`, `/set min_dev 12`.

Правила отправки: объявление подходит под фильтры профиля **и** (рейтинг ≥ порога **или** ниже рынка ≥ порога);
не старше `NOTIFY_MAX_AGE_HOURS`; не скрыто; не дубль. Повтор по тому же объявлению — только при снижении цены
на ≥ `REPRICE_NOTIFY_PCT` %. Уникальный ключ в БД (`listing, chat, event`) исключает дубли даже при перезапуске.
Без токена бот работает в режиме-заглушке: сообщения пишутся в лог и видны в мониторинге.

## Начальные настройки поиска

Создаются при первом запуске (всё редактируется во вкладке «Настройки», в «Ленте» через 💾 или командой `/set`):
бюджет 500 000 – 1 000 000 ₽; BMW, Mercedes-Benz, Audi; Ростовская обл., Краснодарский край и соседи (Адыгея,
Ставрополье, Волгоградская и Воронежская обл., Калмыкия); приоритет частным продавцам (+3 балла к рейтингу,
настраивается); отдельный профиль «Дешевле рынка на 10%+».

## Как считается оценка

1. **Аналоги** подбираются ступенями: точные в регионе → по стране → год ±2, объём ±0,5 → модель, год ±3 → модель, год ±5.
   Берётся первая ступень с ≥6 аналогов; иначе лучшая с ≥3 (достоверность снижается); иначе «недостаточно данных».
2. **Дубли** (VIN либо одинаковые марка/модель/год/объём/КПП/пробег/регион) схлопываются; помеченные дубли в расчёт не идут.
3. **Выбросы**: модифицированный z-score по MAD на ln(цены) > 3,5 отбрасываются.
4. **Поправки** на год (по умолчанию 4,5%/год, при ≥10 аналогах — оценка по данным методом Тейла–Сена) и пробег (0,5% за 10 тыс. км).
5. **Рынок** = взвешенная медиана скорректированных цен (вес падает с расхождением в годе/пробеге/регионе/КПП),
   диапазон — 25–75-й перцентили. **Отклонение** = (рынок − цена) / рынок.
6. **Достоверность** = f(число аналогов, разброс, ступень подбора, полнота данных об авто).
7. Используются **цены предложений**, не сделок. Показывается «ожидаемая цена сделки» = рынок × (1 − 5%) — это
   допущение (`asking_discount`), а не измеренная величина.

**Рейтинг 0–100** — взвешенная сумма: цена к рынку (45, сжимается к нейтральному при низкой достоверности),
ликвидность (15), пробег к возрасту (10), возраст (8), состояние по тексту (10), история цены (4), достоверность (8) +
бонус частнику. Состояние по тексту оценивает только ключевые слова и **не заменяет осмотр**. Признаки ДТП/неисправностей/
скрутки/проблем с документами и «подозрительно дёшево» (≥35% ниже рынка) выдают предупреждения и ограничивают
рейтинг значением 69. Пороги 85/70/50 и веса настраиваются. Ликвидность — экспертная популярность модели, уточняемая
возрастом активных объявлений (при ≥5); при нехватке данных это явно помечено.

## Архитектура

```
Источники (adapters) ─► SourceRunner ─► Pipeline ─► БД (Listing, PriceHistory, Notification, SourceState)
 demo / apiad_*          опрос, ретраи    нормализация → дубли → история цены → оценка → рейтинг
                                                         │
          FastAPI (/api, auth, rate limit) ◄─────────────┤──► Notifier ─► Telegram (aiogram) / лог
          React SPA (лента, аналитика, мониторинг)       └──► maintenance (пересчёт, деактивация устаревших)
```
Один процесс (asyncio): API, опрос каждого источника в своей задаче, обслуживание и бот. Для одного пользователя это
проще и надёжнее набора контейнеров с брокером; компоненты разделены на модули и при необходимости выносятся в отдельные
процессы. Неизменённые объявления при повторном получении лишь «касаются» `last_seen_at` (без пересчёта). Состояние
(курсор, счётчики, ошибки, паузы, уведомления) хранится в БД — после перезапуска продолжается с того же места.
Корректное завершение: событие остановки, отмена задач, закрытие HTTP-клиентов и БД.

Отклонение от предложенного стека: вместо готовой UI-библиотеки — собственный CSS (~7 КБ) + Recharts для графиков:
меньше зависимостей и размер сборки, интерфейс полностью под контролем.

## Безопасность
* Секреты — только в `.env`/окружении; в `APP_ENV=production` приложение не стартует с `AUTH_PASSWORD=change-me`
  или коротким `AUTH_SECRET`.
* Панель: пароль → подписанный токен с TTL (HMAC-SHA256); ограничение попыток входа (10 за 5 мин с IP) и общий лимит
  запросов API. **Выставляя сервис в интернет, ставьте перед ним HTTPS-прокси (Caddy/nginx).**
* Telegram: доступ только зарегистрированным чатам. Внешние URL фото проходят проверку схемы (http/https).
* Контейнер работает не от root. Входящие данные валидируются (цена, год, пробег, марка).

## Тесты
```bash
cd backend && pip install -r requirements-dev.txt && python -m pytest -q     # 100 тестов, ~40 с
cd ../frontend && npm run typecheck
```
Покрыто: нормализация, дубли, оценка (устойчивость к выбросам, поправки, недостаток данных), рейтинг (риски, веса,
пороги), фильтры (SQL и Python-реализации дают одинаковый результат на 14 наборах), выгодные предложения,
уведомления (формат, антидубли, снижение цены, пауза, повтор после сбоя отправки), восстановление после ошибок
источника, ретраи/лимиты HTTP, ApiAd на подменённых ответах (**по описанию, не по реальному API**), API и авторизация,
запуск всего приложения в демо-режиме без ключей, сохранение данных после перезапуска.

## Известные ограничения
* Реальные источники не проверены (нет ключей). Формат `params` ApiAd, лимиты, цена и задержка неизвестны.
* Фото в демо отсутствуют (плейсхолдер); в Telegram фото отправляются, если источник отдал URL.
* Оценка строится по ценам предложений и ограничена объёмом собранной базы: в первые дни работы реальных источников
  аналогов мало, достоверность будет низкой — это отображается явно.
* Поколения/модели описаны для BMW, Mercedes-Benz и Audi (`backend/app/catalog.py`); комплектации в оценке пока не учитываются.
* Анализ состояния — по ключевым словам описания, не по фото и не по истории автомобиля (VIN-проверки нет).
